# Project context engineering

Inspect existing project documentation and memory before adding a new store. Keep authoritative facts in one place; link to them from summaries instead of copying them everywhere. Do not modify a protected memory system without the user's authorization.

1. Find the current outcome, scope boundaries, owners, milestones, dependencies, and acceptance evidence. Record source locations and their observation dates.
2. Separate verified facts, decisions, assumptions, open questions, and historical material. For conflicting sources, surface the conflict and identify who can resolve it; do not silently choose the convenient version.
3. Maintain a compact project brief and decision record only where equivalent artifacts do not already exist. A decision needs the choice, reason, consequences, owner, and conditions for reconsideration.
4. Give volatile facts a refresh condition. Cached information about deployments, prices, credentials, laws, or delivery status needs current verification before consequential use.
5. Build a handoff around the exact current state: completed work with evidence, unfinished work, blockers, next executable action, and relevant paths. Exclude secrets and unnecessary personal information.

Validate the context by answering the project's next real decision from the artifacts. If the answer requires guessing or contradicts the source, repair the context before calling the handoff complete. State what is verified now and what is memory-derived.
