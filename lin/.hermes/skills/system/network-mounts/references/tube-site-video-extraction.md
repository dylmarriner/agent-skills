# Tube Site Video Extraction

> Technique for downloading videos from sites running custom video players (Flowplayer, JWPlayer, KT Player) with session-tokenized CDN URLs that yt-dlp can't parse.

## Detection: When yt-dlp fails

Standard yt-dlp failure signs for custom tube sites:

- `ERROR: [generic] Unable to extract flashvars` — the generic extractor can't parse the non-standard player
- `WARNING: [generic] Untested major version` — custom Flowplayer/JWPlayer fork
- Only downloads preview clips (28s preview vs 22min full video)
- The page source has `function/0/` URL prefixes — these are JS-processed URLs

## Workflow

### 1. Check page source for video URLs

```javascript
// In browser console:
document.querySelectorAll('script').forEach(s => {
  if (s.textContent && s.textContent.includes('.mp4')) {
    let matches = s.textContent.match(/https?:[^"'\s]*(?:\.mp4|\.m3u8)[^"'\s]*/g);
    if (matches) console.log(matches);
  }
});
```

Common places video URLs appear:
- **JSON-LD** (`<script type="application/ld+json">`) — has `"contentUrl"` fields (usually 720p)
- **Inline player config** — object with `video_url`, `video_alt_url`, `video_alt_url2`, `video_alt_url3` (360p, 480p, 720p, 1080p)

### 2. Check JSON-LD for contentUrl

The schema.org `VideoObject` often contains a `contentUrl` pointing to a working video (typically 720p):

```javascript
var ld = JSON.parse(document.querySelector('script[type="application/ld+json"]').textContent);
console.log(ld.contentUrl);
```

### 3. Capture CDN URL from network requests

Play the video, then capture the CDN URL:

```javascript
// Clear old entries first
performance.clearResourceTimings();

// Play the video, wait, then:
performance.getEntriesByType('resource').map(e => e.name)
  .filter(n => n.indexOf('cdn') > -1 || n.indexOf('bxcdn') > -1 || n.indexOf('.mp4') > -1);
```

### 4. Download with curl

```bash
# Get fresh cookies from browser:
document.cookie  # in browser console

# Download with cookies + referer:
curl -L -o "video.mp4" \
  -H "Referer: https://site.com/" \
  -H "User-Agent: Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36" \
  -H "Cookie: PHPSESSID=xxx; kt_tcookie=1" \
  "<CDN_URL>"
```

### 5. Try get_file endpoint with cookie

Some sites have a `get_file` endpoint that redirects to the CDN:

```
https://site.com/get_file/39/<hash>/<id>/<id>_1080p.mp4/
https://site.com/get_file/39/<hash>/<id>/<id>_720p.mp4/
https://site.com/get_file/39/<hash>/<id>/<id>.mp4/          # 480p default
```

URLs in page source often have `function/0/` prefix — the JS player processes these dynamically. Hashes in page source also expire. Use browser to get fresh tokenized URLs.

## Pitfalls

- **Session-tokenized CDN URLs** expire within minutes. You must capture the CDN URL fresh from browser network requests while the video is playing.
- **`function/0/` prefix** in page source URLs means the actual URL is dynamically generated by obfuscated JS (often in kt_player.js or similar). The prefix "function/0/" means "call function at index 0 to process this URL."
- **Premium content** — if the CDN only serves a 28-second preview, the full video requires authentication (login/premium). The `get_file` endpoint may check session validity.
- **youtube-dl/yt-dlp with cookies**: `--cookies-from-browser firefox` may not help if the site uses custom JS-based URL processing rather than standard HTTP video delivery.
- **Ad/popunder redirects** — tube sites often redirect to affiliate pages (CandyAI, etc.) after navigation. Use the embed URL if available (`/embed/<id>`) which has fewer ads.

## When to use the browser approach vs. yt-dlp

| Situation | Approach |
|-----------|----------|
| YouTube, Vimeo, Twitter, Twitch | yt-dlp direct |
| Tube site with standard HTML5 video | yt-dlp with `--cookies-from-browser` |
| Tube site with custom player, 404 on direct URLs | Browser → page source → network capture → curl |
| Premium/token-gated content | May not be possible without auth |
