# Comprehensive Session Search

## The problem

The built-in `session_search()` tool uses FTS5 and often returns only a handful of recent sessions (default ~5). When the user asks about conversations from "last month" or specific URLs/downloads, session_search may return nothing even though the data exists in the full database.

## The database

Hermes stores ALL session data (CLI + Telegram + other platforms) in a SQLite database at:

```
~/.hermes/state.db
```

This database has **544+ sessions** (vs session_search showing ~5). It contains two key tables:

- `sessions` — session metadata (id, source, model, started_at, message_count)
- `messages` — all message content with role, timestamp, token counts

The `source` column in `sessions` distinguishes between `cli` and `telegram` sessions.

## Full-text search (fastest)

```bash
sqlite3 ~/.hermes/state.db "
SELECT m.content FROM messages m
JOIN messages_fts fts ON fts.rowid = m.id
WHERE messages_fts MATCH 'pimpbunny'
AND m.role = 'user'
ORDER BY m.timestamp DESC
LIMIT 20;
"
```

The FTS index is on `content + tool_name + tool_calls` combined.

## LIKE search (broader, slower)

```bash
sqlite3 ~/.hermes/state.db "
SELECT m.content FROM messages m
JOIN sessions s ON m.session_id = s.id
WHERE m.role = 'user'
AND m.content LIKE '%eporner%'
ORDER BY m.timestamp DESC
LIMIT 20;
"
```

Use `LIKE '%keyword%'` for partial matches that FTS might miss.

## Check session counts

```bash
sqlite3 ~/.hermes/state.db "
SELECT COUNT(*) FROM sessions;
"
```

```bash
sqlite3 ~/.hermes/state.db "
SELECT COUNT(*), source FROM sessions GROUP BY source;
"
```

## Search for tool names or patterns

```bash
sqlite3 ~/.hermes/state.db "
SELECT m.content FROM messages m
WHERE m.tool_name = 'terminal'
AND m.content LIKE '%yt-dlp%'
ORDER BY m.timestamp DESC
LIMIT 10;
"
```

## Grep session JSON files (fallback)

If state.db isn't available (e.g. on a machine where Hermes keeps session files instead):

```bash
cd ~/.hermes/sessions/
grep -l -i "keyword" session_2026*.json 2>/dev/null | head -10
```

Then extract URL content from the matched files:

```bash
python3 -c "
import json, sys
for f in sys.argv[1:]:
    with open(f) as fh:
        data = json.load(fh)
    for m in data.get('messages', []):
        c = m.get('content', '')
        if isinstance(c, str) and 'keyword' in c.lower():
            print(f'{f}: {c[:200]}')
" session_file1.json session_file2.json
```

## Platform-specific search

Search only Telegram sessions:

```bash
sqlite3 ~/.hermes/state.db "
SELECT COUNT(*) FROM messages m
JOIN sessions s ON m.session_id = s.id
WHERE s.source = 'telegram'
AND m.role = 'user'
AND m.content LIKE '%keyword%';
"
```

## When session summaries conflict with reality

Session summaries are generated by the AI and may contain incorrect claims (e.g. "download failed with 410" when the actual full transcript shows a retry succeeded). Always cross-check summaries against:

1. The raw session messages in state.db
2. Actual output files on disk: `stat /path/to/output/file.mp4`
3. `.part` files that indicate interrupted downloads

The full message content is the ground truth — summaries are fallible.
